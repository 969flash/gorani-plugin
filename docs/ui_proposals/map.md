# 대지검토 패널 UX/UI 스펙 — 안 B「지도 중심」

- 작성 2026-10-07. 근거: `docs/deliverables.md`(요약·A.2·A.4·B·C 공통·E), `docs/data_sources.md` §0·§2.4, `CLAUDE.md`.
- 옛 기존 패널(탭 3개)은 제약 파악용으로만 봤다. 브리지 배관(`send` 큐 / `window.app.receive`)은 그대로 쓰고, 화면 구조는 새로 짠다.

---

## 1. 요약 — 설계 원칙

1. **지도가 화면 전부다.** 480×900 창에 Leaflet 지도가 꽉 차고, 나머지 UI는 지도 위에 얹힌 검색바 1개와 하단 드로어 1개뿐이다.
2. **"어디까지 가져올지"는 눈으로 정한다.** 대상지·범위(버퍼/원/사각형)·수치지형도 도엽 커버·결과 범위를 전부 지도 위 도형으로 보여 주고, 반경을 바꾸면 즉시 다시 그린다.
3. **화면은 1개, 드로어 상태는 4개.** `대상지 없음 → 대상지 있음 → 생성 중 → 결과`. 탭·페이지 전환 없음. 옵션은 드로어 안에서 접었다 편다.
4. **경고는 지도와 드로어에 같이 표시한다.** 데이터 없는 구역·기준일 경과·정합 오차는 글로만 쓰지 않고 지도에 해치/점선으로도 보인다.
5. **Rhino 문서 조작은 결과 카드의 버튼 3개(문서에 넣기·.ai 내보내기·폴더 열기)로 끝낸다.** 미리보기는 패널 안에서, 조작은 Python이.

## 2. 사용자·과업 (jobs-to-be-done)

사용자: 사내 건축사·도시설계자. Rhino는 쓰지만 GIS·코드는 모른다. 과업 착수 단계에서 하루 1~3곳 대상지를 돌린다.

| # | 과업 | 성공 기준 | 빈도 |
|---|---|---|---|

| J2 | 주변을 **얼마나** 가져올지 정한다(500 m 기본, 상황 따라 300 m·1 km, 베이스맵 프레임에 맞는 사각형) | 범위 도형이 지도에 보이고, 규모(건물 n동·도엽 n장·예상 시간)를 미리 안다 | 매번 |
| J3 | 3D 컨텍스트를 현재 Rhino 문서에 넣는다 | 버튼 1개, 수십 초 안에, 실패하면 왜인지 안다 | 매번 |

| J5 | 결과를 믿어도 되는지 판단한다(기준일, 높이 추정 비중, 정합 오차, 누락 구역) | 경고가 한국어로, 조치와 함께, 지도 위치와 함께 보인다 | 매번 |

## 3. 정보구조(IA)와 화면 흐름

### 3.1 IA — 레이어 3장

```
[검색바]  지도 위 상단 고정. 주소/PNU 입력 + 후보 드롭다운 + 레이어 토글(⊞)
[지도]    Leaflet 전면. 타일 / 필지(뷰포트) / 대상지 / 범위 / 도엽 커버 / 결과 범위·QA
[드로어]  지도 위 하단. 손잡이 드래그·클릭으로 3단(접힘 64px / 반 360px / 전체 820px)
          내용은 app.state 에 따라 4가지 중 하나
```

### 3.2 상태 전이 (app.state 하나로 관리)

```
            ┌──────────┐ 필지 클릭/검색 선택 ┌──────────┐  [생성] ┌──────────┐ result ┌──────────┐
  init ───▶ │  empty   │ ───────────────▶ │  target  │ ───────▶ │ running  │ ─────▶ │   done   │
            │(대상지 X)│ ◀─────────────── │(대상지 O)│ ◀─────── │ 진행률   │ error  │ 결과카드 │
            └──────────┘  대상지 전부 제거  └──────────┘  취소/오류 └──────────┘ ◀───── └──────────┘
                                                ▲                                        │
                                                └──────── [범위 바꾸기] / 필지 클릭 ──────┘
```

- `empty`·`target`·`done` 에서는 지도 상호작용(필지 클릭·반경 변경)이 열려 있다. `done`에서 대상지·반경을 바꾸면 결과 카드는 "이전 결과" 라벨로 흐려지고 `target`으로 돌아간다(결과 폴더는 그대로).
- `running` 동안 지도는 보되 클릭은 막는다(드로어에 [취소]).
- 모달은 **하나**뿐: 첫 실행·DB 없음 차단 오버레이(§5.6). 나머지는 전부 드로어·토스트.

### 3.3 한 번의 흐름(해피 패스, 클릭 수)

1. 검색바에 "성수동2가 277-17" 입력 → 후보 1개면 즉시 지도 이동 + 대상지 지정 (클릭 1)
2. 지도에서 옆 필지 클릭 → 합필 (클릭 1). 드로어가 반 높이로 올라와 범위 500 m 버퍼가 그려짐
3. [컨텍스트 생성] (클릭 1) → 진행률 → 결과 카드
4. [문서에 넣기] (클릭 1) → Rhino에 Import·줌. 끝.

지도 스타일: 필지선 `#8a8a85` 1px / hover 채움 10 % / 대상지 `--accent` 1.5px + 채움 35 % / 범위 `--accent` 1px 실선 + 채움 6 % / 도엽 `#5c5c58` 점선 1px + 미보유 사선 해치(SVG pattern) / 결과 범위 `--fg` 1.5px 실선 / 베이스맵 프레임 `#5c5c58` 실선 1px / QA `--qa` 점 반지름 4.

타이포: 상태 1줄 `--fs-md` 600, 본문 `--fs`, 칩·힌트 `--fs-sm`, 메타 `--fs-xs`. 버튼 높이 36(primary 44).

## 10. 접근성·키보드

- 포커스 순서: 검색 → 레이어 토글 → 지도(Leaflet 기본 키보드 패닝/줌) → 드로어 손잡이 → 드로어 내용 순.
- 드로어 손잡이 `role="button" aria-expanded` + ↑/↓ 로 3단 전환, `aria-controls="drawer_body"`.
- 필지 폴리곤은 마우스 전용이 현실. 대안 경로 = 검색(키보드만으로 대상지 지정 가능). 검색 드롭다운 ↑↓ Enter Esc.
- 세그먼트는 `role="radiogroup"`, ←→ 이동. 토글은 `<input type=checkbox>` + 라벨.
- 단축키(드로어·지도에 포커스 있을 때): `Enter` 생성/문서에 넣기(현재 primary), `Esc` 취소·시트 보기 닫기, `Del` 마지막 칩 제거, `←/→` 시트 이동, `/` 검색 포커스.
- 진행률 `role="progressbar" aria-valuenow`, 토스트 `aria-live="polite"`, 오류 블록 `role="alert"`.
- 색만으로 구분하지 않음: 경고는 아이콘(⚠·✕·ⓘ) + 색 띠, 지도 범위는 라벨 텍스트("500 m", "지형 없음") 병기. 대비 4.5:1 (`--fg-3` 는 힌트에만).
- 터치는 고려 안 함(데스크톱 Rhino). 창 최소 400×700까지 깨지지 않게(드로어 반 높이 300).

## 11. 구현 메모

### 11.1 파일·구조

- `scripts/site_ui.html` 1파일(마크업 + `<style>` + `<script>`). Leaflet·Pretendard는 호스트가 로드 시 인라인 주입(기존 방식).
- JS 전역 하나: `app = {state:'empty', lots:[], extent:{radius:500, shape:'buffer', center:null}, options:{…}, result:null, map:{…}}`. `render()` 한 함수가 `app.state`로 드로어 내용을 `innerHTML` 템플릿 4개 중 하나로 갈아끼운다(가상 DOM·컴포넌트 없음). 이벤트는 `#drawer_body`에 위임 1개.
- `receive(msg)`는 `switch(msg.type)`로 `app` 갱신 → `render()` / `renderMap()` 호출. 지도 갱신은 레이어별 `clearLayers()+addData()`.
- 옵션은 `localStorage.udt_options` JSON 1키.

### 11.2 Leaflet 레이어 (전부 `L.geoJSON` 또는 기본 벡터, `preferCanvas:true`)

| 변수 | 내용 | 갱신 시점 |
|---|---|---|
| `tileLayer` | WMTS/OSM | init, tileerror 폴백 |
| `parcelLayer` | 뷰포트 필지(줌 ≥17) | `moveend` 디바운스 → `parcels` |
| `targetLayer` | 대상 필지 + 합집합 | `target_state` |
| `extentLayer` | 범위. 원·사각형은 `L.circle`/`L.rectangle` 클라이언트 즉시, 버퍼는 `extent` 응답 | 반경·형태 변경 |
| `sheetLayer` | 도엽 경계 + 미보유 해치 | `extent` |
| `frameLayer` | 베이스맵 프레임(축척별 사각형, 클라이언트 계산: 용지 mm × 축척 / 중심) | 옵션 변경 |
| `resultLayer` | 결과 클리핑 범위 + QA 점 | `result` |
| `originMarker` | 중심(원점) | `target_state` |

원·사각형 드래그: `extentLayer`에 `mousedown` → `map.dragging.disable()` → `mousemove`로 중심 갱신 → `mouseup`에서 `set_extent` 1회. 반경 핸들은 원 동쪽 끝 `L.circleMarker` 1개 드래그. 플러그인 없이 40줄.

### 11.3 성능

- 필지 폴리곤은 줌 ≥17·`limit 5000`·canvas 렌더(기존). 뷰포트 밖 레이어 교체 시 `clearLayers` 대신 새 `L.geoJSON` 만들고 이전 것 `remove`(깜빡임 최소).
- `extent`는 Python이 shapely 버퍼 + 도엽 교차 + 건물 bbox count 만 — 100 ms 급. 반경 세그먼트 연타 시 마지막 요청만 반영(JS가 `seq` 붙여 보내고 늦은 응답 무시).
- 시트 SVG는 수 MB 가능 → `preview_sheet`는 1장씩, JS `Map` 캐시. `<img>`로만 렌더(DOM 주입 금지 — 폰트·id 충돌·느림).
- `progress`는 Python이 단계마다 + 긴 단계(TIN·3dm 쓰기)는 2초마다. `log`는 10줄 묶음.
- 드로어 높이 전환은 `transform: translateY` + `transition .2s`. 지도는 `map.invalidateSize()` 호출 없음(드로어가 지도 위에 떠 있으므로 지도 크기는 고정). 결과 범위 fit 은 `fitBounds(…, {paddingBottomRight:[0, drawerHeight]})`.

### 11.4 Python 쪽 메모(계약 준수용)

- `cmd_site.py`: 명령 → 로직 호출 → 푸시. `run`은 서브프로세스(python3) 또는 같은 프로세스 — 어느 쪽이든 단계마다 `progress`를 푸시하고 `cancel` 플래그를 단계 경계에서 확인.
- `import_3dm`·`export_ai`·`open_*`·`zoom_rhino` 만 Rhino 문서를 만진다(베이커 모듈).
- `extent`·`target_state`의 `prewarn`은 `result.warnings`와 같은 스키마 — JS 렌더 함수 하나.
