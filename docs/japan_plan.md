## 0. 결론

1. 일본판을 별도 플러그인으로 만들지 않는다. 지금 Global 모드가 일본 대상지에서 쓰는 데이터를 공공데이터로 바꾼다. 데이터 모드도 새로 만들지 않는다.
2. 새로 받는 데이터는 둘이다. 건물은 PLATEAU 팩이고, 지형은 일본 GSI(国土地理院 — 일본 국토교통성 소속 측량 기관, 한국 국토지리정보원과 다른 곳)의 5 m 표고 타일을 실행 중에 받는다. 도로·수계·녹지·철도는 지금처럼 OSM을 쓴다.
3. PLATEAU 도시 데이터셋 하나를 팩 하나로 만들었다(`jp<시구정촌코드>_context.db`, 경위도). 306곳, 건물 2,940만 동(도시 경계 중복 포함), 압축 2.69 GB. 가장 큰 요코하마가 압축 80.5 MB로 한국 최대 팩(제주시 126 MB)보다 작아 더 나누지 않았다 [로컬].
4. 일본 팩은 Hugging Face의 지금 데이터셋 `jp/` 폴더에 두고, 매니페스트는 `jp/manifest.json`으로 따로 둔다(§2). 일본 데이터는 국외 반출 제한이 없어 국내 서버가 필요 없다.

## 2. 팩 분할·형식 (실제로 만든 것)

- **단위·이름**: PLATEAU 데이터셋 하나 = 팩 하나, `jp<코드>_context.db`(+`.xz`), HF `jp/jp<코드>_context.db.xz`. 도시마다 최신 연도판 하나.
- **매니페스트를 따로 둔 이유**(계획에서 바꿈): 한국 팩 올리기(`dev_deploy.py upload`)는 로컬 한국 매니페스트로 공개 매니페스트를 다시 쓴다. 같은 파일에 넣으면 main에서 한국 팩을 올릴 때마다 일본 항목이 사라진다. 따로 두면 서로 덮지 않고, 한국 대상지는 일본 목록(109 KB)을 받지 않는다. 구버전 플러그인은 일본 매니페스트를 아예 모른다.
- **좌표**: 경위도 소수 6자리(0.11 m — 원천 외곽은 지도정보레벨 2500, 평면 1.75 m). 매니페스트 `bounds`도 경위도 `[서, 남, 동, 북]`.
- **표**: 런타임(`context_db._building_from_row`)이 읽는 한국 칸 이름만 둔다. `ngii_kind` = 원천 용도 코드, `usability`는 런타임에 `constants.PLATEAU_USE`로 바꾼다(표를 고쳐도 팩을 다시 올리지 않는다). `src_key` = `plateau:<gml:id>`, `building_id` = 코드 × 10⁷ + 순번, 기준일은 `data_sources`(연도판 말일).
- **결측값** [로컬]: 층수 `9999`·높이 `-9999` = 모름 → 0. 구니타치는 층수 9999인 6,155동(13.6 %)이 모두 용도 `461`(불명)이었다.
- **경계 중복** [로컬]: 도시 데이터셋은 경계 3차 메시를 통째로 담는다. 도쿄도 팩끼리 같은 gml:id(국립·국분지 13,245동) — 런타임이 `src_key`로, 다른 도시 팩의 같은 자리 건물은 새 연도 팩 것을 남겨 거른다.

## 3. 빌드·올리기 — `scripts/dev_plateau.py`

```
python3 scripts/dev_plateau.py catalog          # CKAN → data/raw/plateau/catalog.json (306곳)
python3 scripts/dev_plateau.py build [코드 …]   # build/packs/jp/ — 같은 연도 팩은 건너뛴다
python3 scripts/dev_plateau.py upload           # HF jp/ 팩 → jp/manifest.json → README(데이터셋 카드)
```

- 실측(2026-10-21, 이 Mac 8 작업): 받기 18.1 GB(zip 1.46 TB 중 건물 GML만 Range로), 전체 약 1.5시간, 실패 0. 10곳은 GML 이름에 `_op`가 없어 첫 판에서 빠졌다가 고쳐 다시 만들었다(幸手市·大館市 등).
- HF 업로드: `jp/` 307개(팩 306 + 매니페스트), README를 Gorani 이름 + PLATEAU 출처·가공 고지로 바꿨다(옛 이름 UrbanDesignTool이 남아 있던 것도 함께 정리).
- 갱신: PLATEAU 새 연도판이 나오면 `catalog` → `build`(바뀐 도시만) → `upload`.

## 4. Hugging Face 전략 평가 — 타당하다, 단 저장소·CDN으로만 쓴다

**타당한 이유**
- 일본 데이터는 국외 반출 제한이 없고 CC BY 4.0과 호환된다.
- 무료이고 CDN·Range를 지원한다. 익명 받기 한도는 IP당 5분에 3,000회다 [로컬: 응답 헤더 `ratelimit-policy: q=3000;w=300`].
- 필지 팩이 이미 HF에 있다. 새 계정·서버·비용이 없다. 매니페스트가 팩마다 주소를 적으므로 HF에 문제가 생기면 주소만 바꿔 옮긴다.
- CORS를 허용한다 [로컬]. 웹판(Pyodide)도 바로 받는다.

**주의할 점**: 무료 공개 저장 공간은 'best-effort'다(HF 문서: 처음 몇 GB를 넘으면 다른 사용자에게 가치 있는 것만). 지금 한국 약 8 GB + 일본 2.69 GB. LOD2·텍스처·원본·Parquet 사본처럼 용량만 늘리는 것은 올리지 않는다. 막히면 PRO(월 $9, 공개 저장 10 TB)나 다른 정적 호스팅으로 주소만 바꾼다.

**HF로 하지 않을 것**: 빌드 연산(Jobs는 유료 — 이 Mac이면 된다), 지리원 타일 미러(실시간 읽기만 신청 면제), 일본 OSM 미리 굽기(ODbL 재배포 의무·갱신 부담 — Overpass 실패가 잦으면 다시 본다), 한국 수치지형도 팩 옮기기(공간정보관리법 제16조).

## 6. 확인 필요·남은 일

- **일본 測量法**: PLATEAU 공공측량 성과 제약과, GSI 타일을 3dm 메시로 남기는 것이 승인 대상인지 공개 전에 확인한다.
- **`measuredHeight` 기준**: 지반 최저점부터 최고점까지인지 표준제품사양서에서 확인한다.
- **용도 코드 없는 도시**: 2020년도판 일부(豊中市 등)는 `bldg:usage`가 없다 — 용도 도면이 비어 나온다.
- **Overpass**: 2026-10-21에만 공개 서버 4곳이 두 번 모두 막혔다. 일본은 건물·지형으로 만들지만 도로가 빠진다. 잦으면 OSM 미리 굽기를 다시 본다.
- **매니페스트 공지**: `notices`·`update` 문구가 한국어 하나뿐이다 — 언어별 문구는 다국어 쪽과 함께 정한다.
