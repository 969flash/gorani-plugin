# 04a. 공간 기본도 데이터 인벤토리 — 필지·건물·도로·지형·수계·행정경계·교통망·도시계획·주소

- 작성일: 2026-10-07 (모든 URL 접근일 동일)
- 목적: UrbanDesignTool(Rhino 8 플러그인)의 3dm 컨텍스트 모델·베이스맵(AI)·현황도에 쓸 "기본도" 원천을 레이어별로 고르고, 다운로드 자동화 가능성·좌표계·라이선스·함정을 한 번에 정리한다.
- 표기 규칙: `[공식]` 1차 출처(기관 사이트·데이터 상세 페이지·고시), `[2차]` 블로그·언론·검색 요약, `확인 필요` = 이번 조사에서 직접 열어 확인하지 못함. 기술 식별자는 영문 원문 유지.

### 0.2 이번 조사에서 확인된 핵심 사실 8가지

1. **국가공간정보포털(nsdi.go.kr)은 2023-12-31 종료**되었고 다운로드·API는 브이월드로 옮겨졌다. 옛 URL(`data.nsdi.go.kr`)은 DNS 자체가 안 풀린다. [공식: 공공데이터포털 공지 2024-01-02] `https://www.data.go.kr/bbs/ntc/selectNotice.do?originId=NOTICE_0000000003431`
2. **브이월드 벌크 다운로드는 로그인 필수**다. 데이터 상세 페이지의 다운로드 JS가 `if(menuFnc.loginYn == "N"){ alert("로그인 후 이용해주세요.") }`로 막고, 실제 다운로드 URL은 `/dtmk/downloadResourceFile.do?ds_id=…&fileNo=…`(iframe)다. 500 MB(JS 임계값 512000 KB) 초과 파일은 '선택다운로드'(라온K 전용 프로그램) 경로만 허용된다. 라온K 설치파일은 `/raonkupload/agent/raonkSetup.exe`로 **Windows 전용**이다. [공식: dsId=4 페이지 HTML, curl로 확인] → 세션 쿠키를 들고 스크립트로 받는 것은 가능하나 비공식이며, 500 MB 넘는 zip — 등고선(30185) 9개 전부, 도로경계_선(30180) 2개 전부 — 은 macOS 환경에서는 Windows VM/타 PC 없이는 수령 자체가 불가하다.
3. **연속수치지형도가 레이어별 dsId로 쪼개져 전국 zip으로 제공**된다(EPSG:5179 UTM-K, 연간, CC BY). 건물 30162, **도로경계_선 30180(데이터셋명 기준 선 데이터)**, 도로분리대 30181, 도로중심선 30182, 등고선 30185(총 21건·3페이지 분할), 표고점 30245, 인도 30221, 실폭하천 30207, 하천경계 30248, 하천중심선 30249, 호수 30256, 철도중심선 30235, 교량 30168. 도엽 단위 수치지형도(국토정보플랫폼, EPSG:5186)와는 좌표계가 다르다. 참고: 30182 페이지의 제공기관은 '국토정보지리원'(오타)으로 적혀 있어 메타데이터 검색 시 '국토지리정보원'으로는 안 잡힐 수 있다.
4. **도로명주소 전자지도 6개 공간 레이어가 브이월드 오픈마켓에 승인 절차 없이** 올라와 있다(시도별 SHP, EPSG:5179, 변경발생시 — 실제 2026-09-15 갱신). 다만 건물(30056)·도로구간(30055)은 **CC BY-NC-ND**(영리 불가·변경 금지) 표기. 승인형 전자지도(juso.go.kr)는 공공누리 1유형(출처표시)이라 라이선스가 더 넓다 — 상용 플러그인이면 승인 경로가 안전.
5. **VWorld 2D 데이터 API**: `https://api.vworld.kr/req/data`, `size` 최대 1000 + `page`, `geomFilter`(POINT/LINESTRING/POLYGON/MULTIPOLYGON/BOX) + `buffer`(m 단위, geomFilter 주변 버퍼), `attrFilter`, `crs` EPSG:4326·3857·4019·900913·5179~5188 지원, 응답 `record.total / page.total`. WFS도 `maxfeatures` 최대 1000. 일일 호출 한도 숫자는 문서에서 못 찾음(`OVER_REQUEST_LIMIT` 오류코드만 존재) → `확인 필요`.
6. **지형**: 국토정보플랫폼 '공개DEM'은 90 m 격자(IMG)다(2015 공개). 5 m DEM 공개 여부는 이번에 확인 못 함. 보유 1:5000 도엽의 등고선은 5 m 간격(주곡선/계곡선), 1:1000은 1 m — 등고선 TIN이 1순위.
7. **좌표계가 4종 섞인다**: 수치지형도 도엽 SHP·토지특성·연속지적·GIS건물 = **EPSG:5186**, 연속수치지형도·도로명주소·SGIS = **EPSG:5179**, 서울 UPIS = **EPSG:5174(Bessel)**, API 기본 = **EPSG:4326**. DB 내부 표준은 5186(보유 DB와 동일)으로 통일하고, 5174→5186은 datum 변환이 들어가므로 지적 경계와 겹쳐 검증한다. **주의**: 브이월드 dsId=4·dsId=18 페이지의 '메타데이터 정보' 블록은 '타원체 Bessel / 투영법 TM'으로 적혀 있어 상단 '배포 데이터 좌표계 GRS80, EPSG:5186' 표기와 모순된다 — 페이지 표기를 믿지 말고 로컬 `.prj`와 실제 좌표값(5186이면 서울 X≈190,000~215,000, Y≈540,000~565,000)으로 판정한다.
8. **브이월드에 3D 자산이 있다**: 데이터 카탈로그 포맷 필터 '3D'에 72건, '3차원 시설물(LoD3)'·'3차원 시설물(LoD4)' 항목(지도조회 유형, 다운로드 아님)이 존재한다. [공식: `https://www.vworld.kr/dtmk/dtmk_ntads_s001.do` 포맷 필터 `data-value="3D" data-count="72"`] 72건의 정체(건물/교량/지형)·다운로드 가능 여부·형식(3DS/XDO 등)·라이선스는 이번에 조사하지 못했다 → `확인 필요`. 3dm 컨텍스트 모델이 핵심 산출물이므로 후속 1순위.

### 0.3 권장 파이프라인(요약)

- 서울 전역 DB(벌크, 연 1~2회): 연속수치지형도 9개 레이어(건물·도로경계_선·도로중심선·인도·등고선·표고점·하천경계·실폭하천·호수) + GIS건물통합정보(월) + 도로명주소 6레이어(변경발생시, 관측상 월 단위) + UPIS(월, 보유) → 모두 EPSG:5186으로 재투영해 보유 SQLite/GeoPackage에 적재.
  - **전제 조건**: 9개 중 등고선(30185, 9개 zip 542~1,232 MB)과 도로경계_선(30180, 740·626 MB)은 전량 >500 MB라 라온K(Windows exe)로만 받을 수 있다. 이 프로젝트가 macOS이므로 (a) Windows VM/타 PC에서 1회 수령하거나, (b) 국토정보플랫폼 '연속수치지형도' 탭에서 서울 영역만 선택 다운로드하거나, (c) 1:5000 도엽 단위 수치지형도를 반복 수령해 접합하는 경로 중 하나를 먼저 확정해야 한다(b·c의 실제 용량·건수 제한은 `확인 필요`).
- 대지 주변 즉시 조회(플러그인 런타임, 반경 300~500 m): 2D API `LT_C_BLDGINFO`(높이 포함), `LT_L_N3A0020000`(도로폭), `LT_C_WKMSTRM`, `LP_PA_CBND_BUBUN` — 기존 BOX 타일 수집 코드 재사용.
- 지형: 등고선·표고점 → **브레이크라인(성/절토 `F0030000`, 옹벽·석축 `F0040000`; 도로경계·하천경계는 소프트 브레이크라인)을 넣은 제약 Delaunay(constrained TIN)** → Rhino Mesh. 도로면·하천면은 TIN에 투영. 브레이크라인 없이 등고선만 쓰면 옹벽·도로 성토 단차가 뭉개진다(로컬 4도엽 모두 `N3L_F0030000`·`N3L_F0040000` 보유, 옹벽 레이어에 `높이` 필드 있음).

## 4. 결론 — 레이어별 1순위와 대안, 이유

### 건축물
- **1순위: GIS건물통합정보(dsId=18, 월간 전체 + 일간 변동, EPSG:5186, CC BY)** — 보유 DB와 같은 좌표계, 세움터 대장 연계로 층수·용도·사용승인일이 붙고 전국 동일 구조라 확장이 쉽다. 높이는 `LT_C_BLDGINFO.height`(API) 또는 건축HUB `heit`로 보정.
- **대안 1: 연속수치지형도 건물(dsId=30162, 연간, CC BY)** — 도로·하천·등고선과 같은 측량 원천이라 기하가 서로 맞물린다(베이스맵 일러스트 정합성). 층수 속성 있음.
- **대안 2: 도로명주소 건물(dsId=30056)** — 사용승인 전 건물까지 있어 최신이지만 CC BY-NC-ND.
- 서울 S-Map 3D 모델은 공개 페이지에서 파일 다운로드 메뉴를 찾지 못했고(로그인 후 데이터셋 메뉴는 `확인 필요`), 브이월드 3D 자산 72건·3차원 시설물 LoD3/LoD4의 다운로드 가능 여부도 미조사다. 둘 다 확인되기 전까지 3dm 매스는 외곽선×(층수·높이)로 직접 생성한다.

### 도로
- **1순위: 연속수치지형도 도로중심선(30182, 차로수·도로폭) + 도로경계_선(30180) + 인도(30221)** — 측량 원천이라 건물·하천·등고선과 기하가 맞물리고 CC BY라 가공 배포가 자유롭다. 단 30180은 데이터셋명 그대로 **선 데이터**라 폴리곤화가 필요하고, 두 zip(740·626 MB) 모두 >500 MB라 라온K(Windows)로만 받을 수 있다. 연 1회 갱신도 약점. ("도로를 면으로 가진 유일한 전국 공개 벡터"라는 이전 서술은 과장이었다 — 아래 실폭도로가 이미 전국 도로 면이다.)

- **대안: 공개DEM 90 m(IMG)** — 광역 개요도·음영기복 배경용. 5 m DEM 공개 여부는 후속 확인.
