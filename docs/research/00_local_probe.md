# 00. 로컬 실측 — 이 Mac·이 Rhino·이 데이터로 직접 확인한 사실

조사 문서(01~08)는 웹 자료 기반이다. 이 문서는 2026-10-07에 개발 환경에서 **직접 돌려서** 확인한
결과만 적는다. 추천을 정할 때 이쪽이 우선한다.

환경: macOS, /usr/bin/python3 3.9.6, geopandas 1.0.1 / shapely 2.0.7 / pyogrio / pyproj / requests,
rhino3dm 8.35.0(pip 설치 성공), Rhino 8.35.26251 (Mac), `rhinocode` CLI 사용 가능.
실행 방법: `python3 scripts/dev_rhino_run.py <드라이버.py>` → `result/rhino_jobs/<id>/out/log.txt`.

## 1. rhino3dm으로 Rhino 밖에서 3dm 쓰기 — 된다

python3에서 `rhino3dm.File3dm`으로 쓴 파일을 Rhino 8이 그대로 읽었다.

| 항목 | 결과 |
|---|---|
| 중첩 레이어(부모 `UDT` → `building`·`terrain`·`lot`) + 색 | 보존. `FullPath` = `UDT::building` |
| `Extrusion.Create(PolylineCurve, 12.0, cap=True)` | 읽힘. `IsSolid=True`, 부피 960.0 정확 |
| 격자 `Mesh`(정점 25·면 16) | 읽힘. `IsValid=True` |
| `PolylineCurve` + 객체 UserString(`PNU`) + 객체 이름 | 보존 |
| 파일 단위 Meters → mm 문서에 `_-Import` | 자동 환산(10 m → 10000 mm). 객체 3개 정상 |
| 문서 수준 UserString(`File3dm.Strings`) | **python rhino3dm에는 쓰기 API가 없다**(`Delete`·`DocumentUserTextCount`만). 원점 오프셋 같은 메타는 객체 UserString이나 사이드카 json으로 남긴다 |
| `File3dm.Notes` | 속성 없음 |

→ 컨텍스트 3dm은 Rhino 없이도 만들 수 있다(배치 생성·테스트 용이). 패널에서 "현재 문서에 넣기"는
RhinoCommon 베이크 또는 생성한 3dm을 `_-Import`하는 두 길이 모두 열려 있다.

## 2. Rhino 8 Mac 내보내기 — 레이어 보존 여부 (`_-Export` 스크립트 호출)

레이어 2개(`UDT_TEST_A`·`UDT_TEST_B`)에 사각형 하나씩 넣고 선택 후 `_-Export "<경로>" _Enter…`.

| 형식 | 결과 | 파일 안 근거 |
|---|---|---|
| **.ai** | 성공. 레이어 이름 둘 다 들어 있음. **사용자 Illustrator에서 열어 두 레이어가 따로 보이는 것 확인(2026-10-07)** | `%!PS-Adobe-3.0`, `%%Creator: Rhinoceros`, `%AI5_BeginLayer` 블록 — Illustrator 레거시(AI5) 형식 |
| .dxf | 성공. 레이어 둘 다 | `LAYER` 테이블, `$ACADVER AC1021`(2007) |
| .svg | 성공. 레이어 둘 다 | `<g id="…">` 그룹 |
| .pdf | **스크립트 호출 실패**(`RunScript` False, 파일 없음) | 옵션 프롬프트 순서가 다른 듯 — 필요하면 별도 확인 |

설치된 내보내기 플러그인: `Adobe Illustrator 내보내기`, `Export SVG`, `PDF Export`, `AutoCAD file export`.

→ 베이스맵의 1순위 경로는 **Rhino 레이어에 2D로 그린 뒤 내장 .ai 내보내기**다. 축척 옵션은
`_-Export` 프롬프트에서 고른다(실측 때는 기본값 `_Enter`). 축척·용지 옵션 문자열은 구현 때 확인.

## 6. VWorld 3D(xdworld) DEM 타일 — 서비스 자체가 닫혀 있다 (2026-10-07 재확인)

사용자가 인증키의 서비스 범위를 "모든 API"로 바꾼 뒤 다시 시도했다. 결과는 전부 같다.

| 시도 | 결과 |
|---|---|
| `XDServer/requestLayerNode?APIKey&Layer=dem&Level&IDX&IDY` — https/:8080, 타일 체계 2종(10°·36° level0), Level 6~15, IDY 남/북 기준 | 모두 `<Error code="ERROR_DB_GENERAL">` |
| `XDServer3d/requestLayerNode` 같은 파라미터 | 같음 |
| `XDServer/3DData?Version=2.0.0.0&Request=GetLayer/GetCapabilities/GetLayerExists&Key&Layer=dem` | 같음 — GetCapabilities까지 거부 |
| 파라미터명 변형(apikey/key/Type), 하이픈 없는 키, Referer(등록 도메인·map.vworld.kr) | 같음(이름이 틀리면 `ERROR_SERVICE_PARAMETER_NG`로 구분되므로 파라미터 해석은 정상) |
| **가짜 키** `00000000-…` | **똑같이** `ERROR_DB_GENERAL` → 키를 아예 조회하지 않는다 |
| 같은 키로 2D 데이터 API `LT_C_BLDGINFO` | `OK` — 키 자체는 정상 |

근거: 브이월드는 2019-07-22에 **3D 데이터 Open API를 폐쇄**했다(공개제한 공간정보 크롤링 사건 → 국토교통부 보안관리규정). 이후 3D 공간정보는 "공개제한 공간정보 보안심사" 절차로만 제공한다
([VW LAB 블로그 2018 글의 2019 추가 공지](https://www.vw-lab.com/52), 검색 요약). 타일 체계 역산(2018년 예시 Level 15 IDX 279420·IDY 116121 → level0 타일 36°)도 확인했지만 서버가 키를 받지 않으므로 무의미하다.
브라우저용 WebGL 3D 지도 API 3.0은 지형을 Cesium 엔진 안에서 브이월드 내부 키로 읽는다(예: watershed-3d가 `terrainData.interpolateHeight`로 높이를 얻음) — 서버 다운로드 경로가 아니고 약관상 쓸 수 없다.

**결론: 지형은 브이월드 API로 자동화할 수 없다.** 1순위 = 수치지형도 1:5000 등고선·표고점(브이월드/국토정보플랫폼 수동 다운로드, 5 m 간격), 2순위 = 국토지리정보원 DEM 5 m(국토정보플랫폼, 로그인·대용량 전송, IMG 형식), 보조 = Copernicus GLO-30 30 m(AWS 공개 버킷, 로그인 없음, 서울 타일 `N37_00_E126_00`·`N37_00_E127_00` 존재 확인 — 단 건물이 포함된 DSM이라 도심 지면고로는 부정확).
